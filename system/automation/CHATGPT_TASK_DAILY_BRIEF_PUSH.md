# ChatGPT Task — RB Daily Brief Delivery

Purpose: create the native ChatGPT notification/email experience for the RB
morning brief. This is the delivery shape that produces a ChatGPT email with a
`View message` button and opens directly to a generated ChatGPT message.

RB owns source refresh, canonical state, and the daily brief API/artifacts.
ChatGPT Tasks owns the user-facing ChatGPT message and native notification.
External RB email remains a backup receipt only.

## Product Distinction

There are two very different delivery modes:

1. **Native ChatGPT Task delivery**
   - Sender: `ChatGPT <noreply@tm.openai.com>`
   - Email/button text: `View message`
   - Click behavior: opens the ChatGPT task result message.
   - User experience: the brief is already there.

2. **External RB email delivery**
   - Sender: Todd/RB SMTP or local mail transport
   - Link behavior: can open the RB Custom GPT, but cannot auto-submit a
     prompt or auto-render the brief.
   - User experience: user must send `Show today's RB Daily Brief.`

Todd's preferred UX is mode 1. Mode 2 is acceptable only as backup.

## Schedule

- Time: 5:05 AM Central
- Cadence: daily
- Notification: push enabled in ChatGPT iOS/Android/macOS/web notification settings

## Target Task Prompt

Use this as the ChatGPT Task instruction once the task can retrieve RB's
current brief through the RB Custom GPT action or a secure hosted RB brief
endpoint. The local RB morning pipeline must run first and write
`system/published/daily/latest_brief.json`; the task reads that canonical
artifact through the Action and renders it.

```text
Every weekday and weekend morning at 5:05 AM Central:

Retrieve today's Relationship Builder Daily Brief from RB.

Use the RB Action `getDailyBrief` with `use_cache=true`. Treat the returned
`canonical_brief` as authoritative. Do not research the news live. Do not infer
source freshness. Do not rewrite persistence or action state.

Render it as a concise Chief-of-Staff morning brief:

1. Daily Prep Summary / source health
2. Morning Command Center
3. Top relationship/action priorities
4. Meeting prep and deliverable risks
5. Waiting-on / sent-followup state
6. Suggested loop creation
7. Strategic operator movements only when source-backed
8. Market/operator context only when source-backed
9. What to ignore
10. One narrow question for Todd, if needed

Do not produce a generic restaurant-tech or macro/news summary.
Do not invent stale or missing sources.
If RB data cannot be retrieved, say exactly what retrieval failed and what Todd
should do next.
```

## Notes

- ChatGPT Tasks can proactively run scheduled prompts and send push/email
  notifications when complete.
- The `View message` email is generated by ChatGPT Tasks, not by RB's SMTP
  sender.
- A normal external email cannot reproduce the `View message` behavior because
  it cannot create a ChatGPT task-result message.
- The RB daily automation remains responsible for source refresh, brief
  generation, artifact publication, and backup email delivery.
- The native ChatGPT Task is a presentation and notification surface. It should
  consume the prebuilt canonical artifact, not perform the backend intelligence
  pipeline itself.
- Named Cloudflare Tunnel (not a quick tunnel) is required for stable task
  delivery. See Appendix A in
  `system/CLAUDE_ARCHITECTURE_2026-05-23_RB_9_2_MORNING_DELIVERY_AND_SOURCE_INSTRUMENTATION.md`
  for setup.
- To make native Task delivery canonical, the task needs a retrieval path:
  either the RB Custom GPT action can be used by the task, or RB must expose a
  secure hosted daily-brief endpoint the task can fetch.
