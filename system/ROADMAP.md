### Unified Query Engine (Option B — expanded)

Single conversational query surface across all RB intelligence modules: Micro, Macro, Relationship, Intelligence, Ecosystem, Artifact, Campaign, and Signals.

**The problem it solves:** The GPT currently has 7 fragmented query endpoints and must guess which module to call for a given question. Questions that span modules (e.g., "What do we know about PAR's exit positioning?") require multiple manual calls or return incomplete answers. The user cannot simply ask a question and get a synthesized answer.

**What is built:**

- `system/scripts/query_engine.py` — deterministic NL intent parser + multi-module dispatcher
  - Parses `{ entity, question }` and scores intent against 7 module profiles using keyword signals
  - Dispatches to one or more of: Micro graph, Macro signals/artifacts/entities, Relationship interactions/WMN, Intelligence DB entity summary, Ecosystem tech-stack relationships, Artifact account dossiers, Campaign roster/coverage-gap queries
  - Also activates Signal synthesis (exit/growth/distress) as a trigger-based 8th dispatch when an entity + pattern keyword (exit, positioning, growth, distress, consolidation, m&a, activist) is present
  - Synthesizes a structured `.answer` string + per-module results + source attribution
  - No LLM call — same deterministic pattern as `intelligence_triage.py`

- `POST /query` — single unified API endpoint (`operationId: queryEngine`)
  - Replaces the 7 fragmented query ops in `openapi_gpt.yaml`
  - Net op count: −6 (from 30 → 24), opening room for future additions
  - RB-DEFECT-2026-07-27: the GPT-facing description (server.py docstring + Field descriptions,
    propagated through `openapi.yaml`/`openapi_gpt.yaml` via `validate_openapi_gpt.py --write`)
    had gone stale relative to the engine's actual capability — it still only named the original
    4 modules, so the Custom GPT had no way to discover ecosystem/artifact/campaign dispatch
    existed at all through this endpoint. Updated to name all 7 modules + signals, with the
    operation-level description kept within the 300-char GPT Builder limit
    (`MAX_DESCRIPTION_LEN` in `validate_openapi_gpt.py`).

- GPT routing rule: all intelligence questions route through `queryEngine` first. Module-specific calls are internal only.

**Module routing table:**

| Intent signal | Module(s) dispatched |
|---|---|
| Graph structure, operators, store counts, franchisees | Micro (getMicroGraphSummary) |
| Consumer behavior, brand risk, market signals | Macro signals + entities |
| Who to contact, relationship history, last touch, WMN | Relationship interactions + WMN |
| What do we know about X (broad) | Intelligence DB entity_summary |
| Tech stack, POS/payments/loyalty, incumbent vendors | Ecosystem canonical relationships + research candidates |
| Registered account dossier status (Global Payments, Foods Connected, PAR Technology, Xenial) | Artifact registry + dossier data |
| Conference invites, registration status, coverage gaps, priority invite list | Campaign (campaign_engine.py roster/gaps/priority-list) |
| Signal pattern, exit/growth/distress | Signal synthesis (getEntitySignals) — trigger-based, requires entity + pattern keyword |
| Ambiguous / multi-module | All relevant modules, merged |

**Tests:** `system/tests/test_query_engine.py`
