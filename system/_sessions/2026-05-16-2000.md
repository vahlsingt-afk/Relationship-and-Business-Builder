## What was decided

- RB is the operating layer; Claude is strategist/operator, scripts are the calculator/state machine. This is the cost-discipline principle running through the whole architecture.
- Source-agnostic pattern for any external feed (calendar, email, social). One JSON shape in system/inbox/, multiple possible fetchers, deterministic compute on top.
- Active threads are the lens. Daily brief opens with them; DRR multiplies by thread boost; calendar/email/social overlays cross-reference against thread companies.
- vahlsingt@gmail.com is the operator's primary identity. BridgePoint is secondary (currently the source of calendar data until the personal calendar MCP is connected).
- LinkedIn feed reading is not scraping — it is in-session reading of posts the operator is already entitled to see. Same legal posture as any browser extension.
- Custom GPT is the first non-Cowork client surface (per the earlier AskUserQuestion answer).
- Conversation memory is versioned in git for V0 single-tenant; in V1 SaaS it lives in per-tenant storage.
