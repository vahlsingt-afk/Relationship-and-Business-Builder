## What changed, by priority

### Priority 1 — touchContact projection sync (defects TOUCHCONTACT-PROJECTION-SYNC-001 + TOUCHCONTACT-VALIDATION-CONFLICT-001)

- `mutations.touch_contact(id, date, source)` is a new function that updates `baseline_index.json` and `system/cards/{id}.md` frontmatter in one transaction. The card update is best-effort; baseline rolls back independently. Result dict includes `baseline_updated`, `card_exists`, `card_updated`, `card_prior_last_touch`, `card_reason` ∈ {`replaced`, `added`, `in_sync`, `no_card_exists`, `no_frontmatter_block`, `dry_run`, `card_update_failed:...`}, and `cache_refresh_recommended`.
- `cmd_touch` (CLI) and the FastAPI `POST /touch` endpoint and the MCP `rb.touch` tool all return the structured result.
- `GET /cards/{id}` now returns `canonical.last_touch`, `frontmatter.last_touch`, `frontmatter_in_sync`, and `projection_status` ∈ {`in_sync`, `stale`, `frontmatter_missing`, `canonical_missing`, `no_frontmatter_block`}.
- `system/protocols/P-009_mutations.md` documents the new projection-sync contract.
- `system/scripts/api_smoke_test.py` adds two regression validations: a read-only `projection_status == in_sync` assertion on Jeff Wayman, and a self-reverting `touch` round-trip that fails if the projection sync regresses.
- Jeff Wayman's card was repaired: frontmatter went from `2025-12-29` → `2026-05-12` to match baseline. The mutation was logged in `baseline.sources` as `claude-handoff-2026-05-19`.
- Bonus bug fix in `openapi.yaml`: the `/loops` path was declared twice (lines 50 and 367), so YAML duplicate-key handling silently dropped `getLoops`. The two blocks are now merged. The GPT could still call `getLoops` because FastAPI exposed both routes — but no GPT inspecting the spec would have seen it. The new `validate_openapi_gpt.py` would catch this regression class going forward.

### Priority 2 — stale-source operator hints

- New `REFRESH_SPECS` table in `relationship_signals.py` maps each source (`email`, `calendar`, `messages`, `calls`, `social`, `social_outbound`) to an exact CLI command + a human summary.
- Every stale-source dict now carries a `recommended_refresh = {command, summary, caveat}` block. The caveat is the explicit operational consequence: *"Treat 'no new signals from `<source>`' as unreliable until this source refreshes."*
- `daily_brief.py` and `relationship_signals.py` text renderers surface the caveat and the exact refresh command underneath each stale source.

No unified `refresh_sources.py` script or `POST /refresh_sources` endpoint was added in this pass. Each source's refresh is still its existing local-only fetcher (`fetch_via_session.py`, `fetch_apple_messages.py`, etc.). Adding a unified wrapper is a follow-up; I left it out because exposing source refresh to the GPT requires an auth story we don't have yet, and the local CLI is already enough for the operator.

### Priority 3 — grounding labels on briefs

- Every signal returned by `relationship_signals.build_report()` now has `grounding ∈ {system_detected, inferred, manual_user_provided, stale_source_limited}` and `freshness ∈ {fresh, stale_source_limited}`. The two are orthogonal — `grounding` describes how the signal was produced; `freshness` describes whether the underlying feed is current. Stale sources mark their signals `freshness=stale_source_limited` automatically.
- Reconciliation prompts and `what_to_ignore` items are tagged `grounding=inferred`.
- The report dict now also carries `signal_counts_by_grounding`, `signal_counts_by_freshness`, and a `grounding_legend` block explaining each label.
- `daily_brief.py` "Top priorities" and "Worth attention" sections render the grounding label on each item, plus a one-paragraph legend at the top of the section.

### Priority 4 — openapi_gpt.yaml + validator

- New `system/api/openapi_gpt.yaml` (23 operations), generated by filtering `openapi.yaml` against a curated allowlist. Excluded: `health`, `getStatus`, `getManifest`, `listProtocols`, `getGapDetection`, `validateBaseline`, `addMyPost`, `addEngagement`, `addSocialPost`, `getRecentSessions`, `endSession`. Required ops (`getDailyBrief`, `getRelationshipSignals`, `getCard`, `getLoops`, `closeLoop`, `touchContact`, `saveTestTrace`) are enforced.
- New `system/scripts/validate_openapi_gpt.py` does both jobs:
  - `--write` regenerates `openapi_gpt.yaml` from the full schema + allowlist.
  - Default mode validates: ≤30 ops, required ops present, `servers[0].url` set and non-placeholder, no duplicate operationIds, no drift from full schema.
  - `--diff` prints which ops are in / out of the subset.
  - `--json` emits machine-readable report.

### Priority 5 — Custom GPT prompt hardening

- New top-level section *"Action availability — read this first"* directing the GPT to inspect its actual callable set before claiming an action is unavailable. Closes RB-ACTION-DETECTION-001.
- New rule 12 requires explicit grounding labels (`system_detected` / `inferred` / `manual_user_provided` / `stale_source_limited`) on every priority and signal in a CoS brief. References the new API fields.
- New rule 13 requires explicit handling of stale sources: never present a clean-board summary when half the feeds are stale; always surface the `recommended_refresh.command`.
- New subsection *"Idempotency / already-done responses"* under "Confirmed execution pattern" — if a mutation returns already-done, call the read action and report as "desired state already achieved". Closes LOOP-CLOSE-ALREADY-CLOSED-001.
- New subsection *"Projection sync after touchContact"* documenting the new response shape and the `getCard.projection_status == in_sync` post-validation step.
- Rule 1 rewritten: the GPT subset doesn't expose `getManifest` / `getStatus` / `listProtocols`, so the prompt no longer recommends a ceremonial startup. The first substantive prompt is also the ground-yourself trigger.
- Sample-interaction examples updated to remove references to ops that aren't in the GPT subset (`getGapDetection`, `validateBaseline`).
